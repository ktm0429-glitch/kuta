# kuta

このリポジトリには、接客力向上トレーニングアプリ(`app/`・`apps-script/`・`docs/`)のほか、
別件の資料(MQL5関連のPDF)も保管されています。以下はトレーニングアプリの説明です。

## 接客力向上トレーニングアプリ

アルバイトスタッフが勤務時間外に取り組む、会話力・接客力向上のための研修アプリです。

- 研修の目的は、**接客によってお客様に快適に遊技を続けてもらうこと(遊技時間の延長)**です。
  問題は、遊技中のお客様の不便・迷い(操作がわからない、音が気になる、休憩の仕方がわからない等)に
  気づいて解消する場面が中心です。
- 挑戦するたびに**5問**が出題されます(前回「復習」に入れた問題があれば、そのうち1問+
  最近出ていない問題4問)。
- スタッフは選択肢から選ぶのではなく、**お客様に話しかけるつもりで自分の言葉で回答**し、
  アプリがその場で採点して「確認できたポイント」「自動では確認できなかったポイント」と
  模範解答の例を表示します。
- **5問に回答すると1pt**(点数の良し悪しは問いません)。**1人1日1ptが上限**です。
- ポイントは **Googleスプレッドシート** に記録され、スプレッドシートを開けばそのまま確認できます。
  管理画面では、景品交換(ポイント消費)と、研修の取り組み状況(途中でやめた人を含む)も確認できます。
- 月額費用はかかりません(Googleスプレッドシート・Apps Script・GitHub Pagesの無料枠のみで動作)。

### 全体の仕組み

```
[スタッフのスマホ・PC] ── 画面(GitHub Pages上の index.html 1ファイル)
        │ 通信(登録・問題の取得・完了報告)
        ▼
[Google Apps Script(apps-script/Code.gs)] ──▶ [Googleスプレッドシート(台帳)]
```

スプレッドシートには次の5シートがあり、Apps Scriptが初回実行時に自動で作成します。

| シート | 内容 |
|---|---|
| スタッフ | 店舗・氏名・保有ポイント。初回ログイン時に0ptで行が追加される |
| 完了記録 | 研修を終えるたびに1行追加(出題した問題・合格数・平均スコア・回答内容) |
| 取り組み状況 | 研修を始めるたびに1行追加し、1問答えるごとに更新(回答数・状態「途中/完了」) |
| ポイント調整履歴 | 管理画面で景品交換(ポイント消費)をした記録 |
| 問題 | 研修問題。ここに行を追加・編集すれば、コードを触らずに問題を増やせる |

以前の形式の「問題」シート(選択肢1〜3の列がある形式)があった場合は、Apps Scriptが
「問題(旧形式)」という名前に変えて残し、新しい形式の「問題」シートを作り直します。

### 回答のしかたと採点

回答のしかたは端末によって自動で切り替わります(`app/src/media/browserSupport.ts`)。
**採点の基準は全端末共通で、回答の内容だけ**です。

| 端末 | 回答のしかた |
|---|---|
| Androidスマホ・パソコン(Chrome・Edge等) | マイクに向かって声で答える。話し終えたら、聞き取った文章を確認・修正してから採点する |
| iPhone・iPad、Firefoxなど | 入力欄に文字で答える(iPhoneはキーボードのマイクボタンで声入力も可) |

- iPhone・iPadのブラウザには、話した声を文字にする機能(Web Speech API)が実質的に
  ありません(機能が存在するように見えても結果を返さない場合があるため、iOSは端末の
  種類で判定して常に文字入力にしています)。
- 声で答えた場合、聞き取れなかった(空欄の)ときは採点せず、録り直しか文字入力を案内します。
  聞き取りの間違いを接客の失敗として採点しないためです。
- 声の大きさ・抑揚は、声で答えた場合に**参考として表示するだけ**で、点数には含めません
  (文字で答える端末との公平のため)。
- **音声は保存しません。** 採点はすべて端末(ブラウザ)内で行い、サーバーに送るのは
  スコアと回答内容のテキストだけです。カメラは使いません。

#### 採点方法(`app/src/scoring.ts` の `scoreAnswer()`)

AIが意味を理解して採点しているのではなく、**問題ごとに決めた「確認ポイント」が回答に
含まれているか**を見る方法です(外部AI・有料APIは使っていません)。

1. 問題ごとに2〜3個の確認ポイント(例: 困っている点を確認する/説明・手助けを申し出る/
   お客様の意向を確認する)と、それぞれの言い回し(例: ご説明しますね/説明/ご案内/お手伝い)を
   「問題」シートに登録しておく
2. 回答と言い回しの表記ゆれ(全角半角・カタカナ/ひらがな・記号・空白)をそろえ、
   言い回しのどれか1つが回答に含まれていれば、そのポイントは「確認できた」とする
3. 点数 = 確認できたポイントの数 ÷ ポイントの数 × 100。60点以上(3つ中2つ以上、
   2つなら両方)を合格の目安とする
4. 出玉や当たりを期待させる・負けを取り返すようあおる表現(「出ますよ」「次は当たりますよ」
   「取り返せますよ」など。一覧は `NG_PHRASES`)が含まれていたら注意を表示し、30点を上限にして
   合格の目安にしない
5. 確認できなかったポイントは「自動では確認できなかった」と表示する(言い方によっては、
   できていても自動で確認できないことがあるため、「できていない」とは断定しない)

確認ポイントが登録されていない問題は、予備として模範解答との文字の重なり具合で採点します。
**弱点**: 意味を理解していないため、登録していない言い回しで正しく答えた場合や、否定文
(「ご説明しません」など)は正しく判定できないことがあります。

### ポイントのルール

- 5問に回答すると1pt。1人1日1ptが上限(日付の区切りは日本時間の0時)。
- 同じ日に何回挑戦しても「完了記録」には毎回記録されますが、ポイントは増えません。
- 完了時、サーバー側で「その研修で出題された5問すべてに、空欄でない回答があること」を
  確認してからポイントを付与します。通信の再送で同じ研修が2回届いても、二重には加算しません。
- 研修の途中で画面を閉じたり通信が切れたりしても、同じ日のうちなら続きから再開できます
  (途中経過は端末のブラウザに保存)。
- 採点結果の画面で「次回の研修で、この問題を復習として出題する」を選んだ問題は、次回の
  研修で1問ずつ出題されます(点数が低かった問題は、最初からこの項目にチェックが入ります)。
- スタッフは「店舗+氏名」で識別します。氏名はスペースの有無・全角半角の違いを無視して
  照合するため、「山田 太郎」と「山田太郎」は同じ人として扱われます。
- 機種変更などで別の端末から使う場合も、同じ店舗・同じ氏名で登録すればポイントは
  引き継がれます(ログイン情報・途中経過・復習リストは端末のブラウザに保存されるため、
  途中経過と復習リストは引き継がれません)。
- 同じ店舗に同姓同名のスタッフがいる場合は同一人物として扱われます。その場合は
  片方の方に、名前の後ろに識別用の文字(例: 山田太郎B)を付けて登録してもらってください。

### よくある作業

#### 研修問題を追加・編集する(コード不要)

スプレッドシートの「問題」シートに行を追加・編集するだけです。次にスタッフがアプリを
開いたときから反映されます(ビルド・デプロイ不要)。

| 列 | 内容 |
|---|---|
| ID | 問題の番号(例: q22)。空欄でも出題されるが、行を並べ替えるとIDが変わり復習リストがずれるため、入れておくのがおすすめ |
| 年代 | `20代` / `30〜50代` / `60〜70代` のいずれか(整理用。出題は全問題から共通) |
| 場面 / お客様のセリフ | 画面に表示される問題文 |
| 模範解答 | 採点後に「模範解答の例」として表示する受け答え |
| 確認ポイント1〜3 | 採点で確認すること(例: 手助けを申し出る)。2〜3個 |
| ポイント1〜3の言い回し | そのポイントができていると判断する言葉を「/」区切りで並べる。**1つ目は例として画面に表示される自然な一言**にする。漢字・ひらがなの両方を入れておくと判定が安定する |
| 解説 | その受け答えで、なぜ遊技を続けてもらえるのか |
| 避けたい対応 | NG例 |

※ 年代・場面・模範解答が空の行は出題されません。問題は常に5問以上必要です。

**問題を作るときの注意(コンプライアンス)**

- 目的は「接客によって快適に遊技を続けてもらうこと」です。不便・迷いの解消、休憩の案内、
  居心地のよさにつながる受け答えを正解にしてください。
- 出玉・当たり・台の設定を期待させる言い方、負けを取り返すようあおる言い方、やめたいお客様への
  無理な引き止めは、正解にしないでください(法令・業界ルール上、問題になるおそれがあります)。
- 店舗で提供していないサービスや、確約できないこと(「台を空けておきます」など)を正解にしない
  でください。休憩のルールなどは店舗の規定どおりに案内する前提で書いてください。

#### Code.gs を更新する

1. スプレッドシートの「拡張機能 → Apps Script」を開き、`apps-script/Code.gs` の全文を貼り付ける
2. `var ADMIN_KEY = '...'` を、運用中の合言葉に書き換えて保存する
3. 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン(編集)→ バージョン「新バージョン」→「デプロイ」

**「新しいデプロイ」は選ばないでください。** URLが変わり、アプリから接続できなくなります
(その場合は `app/src/config.ts` のURLを書き換えて画面を再ビルドする必要があります)。

#### 画面を修正する・店舗を増減する

```
cd app
npm install        # 初回のみ
npm run lint       # 文法チェック
npm run build      # app/dist/index.html ができる
cp dist/index.html ../docs/index.html
```

`docs/index.html` をコミットして公開ブランチにpushすると、数分でGitHub Pagesに反映されます。
店舗を増減する場合は `app/src/data/stores.ts` を編集します(既存の店舗IDは変更しないこと)。

#### 別の場所で画面を公開する

`app/dist/index.html` 1ファイルを、公開したい場所(自社サーバーなど)に置くだけで動きます
(JS・CSSはすべてこのファイルに埋め込まれています)。スプレッドシートとApps Scriptは
変更不要です。

### ゼロから設置する場合

1. Googleスプレッドシートを新規作成し、「拡張機能 → Apps Script」を開く
2. 最初から入っているコードを消して `apps-script/Code.gs` を貼り付け、`ADMIN_KEY` を好きな合言葉に変えて保存
3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」、実行ユーザー「自分」、
   アクセスできるユーザー「全員」でデプロイ
   (「このアプリは確認されていません」と出たら「詳細」→「(プロジェクト名)に移動」→「許可」)
4. 発行されたウェブアプリのURL(`https://script.google.com/macros/s/.../exec`)を
   `app/src/config.ts` に貼り付ける
5. 上記「画面を修正する」の手順でビルドし、`app/dist/index.html` を公開する

「問題」シートには、初回アクセス時に21問のサンプル問題が自動で入ります。

### 有料AIで採点する場合の参考

今の採点は無料の簡易方式(登録した言い回しが含まれるかを見る方式)のため、登録していない言い方や否定文を正しく判定できないことがあります。有料AI
(Claude・ChatGPT・Geminiなど)に採点させると、意味を理解して採点でき、フィードバック文も
回答に合わせて作成できます。

内容の採点だけをAIに任せる場合の費用目安(Anthropic公式価格・2026年6月時点、$1=¥150、
1問あたり入力約800・出力約200トークンの想定。スタッフ全員が1日1回研修する前提):

| スタッフ人数 | Claude Haiku 4.5(月額) | Claude Sonnet 5(月額) |
|---|---|---|
| 50人 | 約¥2,000 | 約¥4,000 |
| 150人 | 約¥6,000 | 約¥12,000 |
| 300人 | 約¥12,000 | 約¥24,000 |

声の大きさ・抑揚まで全端末で公平に評価したい場合は、音声を文字にするサービスの費用が加わります。
上司向けの判断資料「音声判定_有料化の検討資料.pdf」も参照してください。
