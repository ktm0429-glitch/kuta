# NotebookLM経由で要点と前提条件を抜き出す

公開資料の読み込みをNotebookLM（nlmコマンド）に任せ、要点と前提条件を出典付きで抜き出す。
目的は資料の下読みであり、資料の主張を検証することではない。

## 0. 実行環境の確認
- `nlm login --check` を実行し、ログイン状態とアカウントを確認する。
- 失敗した場合（nlmが無い、ブラウザが無いクラウド環境、認証切れなど）は、エラー文をそのまま見せて止まる。代わりにClaudeが資料を直接読むなどの別ルートに勝手に切り替えない。

## 1. 送る資料の確認（必須・省略不可）
- 送る予定のURL・ファイルの一覧を見せ、ユーザーのOKをもらってからソースを追加する。
- 次のものが含まれていたら中止し、理由を伝える。
  - EAのソースコード（.mq5 / .mqh / .ex5 など）
  - バックテスト結果、最適化結果、取引履歴、口座に関する情報
  - 自作EAの仕様書・ホワイトペーパー（例: このリポジトリの kutaGOLD_Titan_WhitePaper_JP.pdf）
- 送ってよいのは、ユーザーが明示した公開資料（論文、Webページ、動画、公式ドキュメント、ブローカーの公開仕様など）だけ。

## 2. NotebookLMでの処理
- ノートブック名は `YYYY-MM-DD_テーマ名` とする。
- 各資料について、次を質問して出典付きで回答を得る。
  - 主張・結論は何か
  - その主張が成り立つ前提条件は何か（対象銘柄、期間、時間足、コスト・スプレッド・スワップの扱い、約定モデル、サンプル数、検証期間と選択期間の分離の有無）
  - 書かれていない前提は何か（記載が無いものは「記載なし」と答えさせる）

## 3. 出力の形式
見出しを次の4つに分け、混ぜない。
1. **資料に書いてあること（出典付き）**: 要点と前提条件。資料に出てくる数値（勝率、PF、シャープレシオ、リターンなど）にはすべて「仮説:」を付ける。
2. **記載のない前提条件**: コスト、先読み、サンプル重複、期間分割など、資料から確認できないもの。
3. **判断不能**: 資料どうしで食い違う点や、資料からは判断できない点を「判断不能:」として一覧にする。多数決や言及回数で結論を出さない。
4. **Claudeの考察**: 1〜3と分けて書く。資料の数値を根拠にした結論は出さない。検証するなら、どのデータでどう再計算するかを書く。

## 4. 保存
- 出力を `~/リサーチ/YYYY-MM-DD_テーマ名.md` に保存する（フォルダが無ければ作成）。
- gitリポジトリの中には保存しない。コミットもしない。
